# 校园旧书漂流共享系统的设计与实现

## 摘要

　　在高校校园中，旧书资源的循环利用始终是一个值得关注的议题。每年大量学生面临专业教材、考研资料等学习用书在使用后闲置的问题，这些书籍往往因缺乏便捷的流转渠道而被丢弃，造成资源浪费；与此同时，新生群体、家庭经济困难学生又面临教材购买成本高、二手学习资料获取不便的现实需求。针对上述问题，本系统以"公益共享"为核心理念，设计并实现了一款基于B/S架构的校园旧书漂流共享平台。系统采用前后端分离架构，后端基于Spring Boot框架结合MyBatis实现业务逻辑与数据库交互，前端基于Vue.js框架结合Element-UI组件库构建用户界面，数据持久化采用MySQL关系型数据库。系统实现了用户注册登录与审核、图书信息发布与审核、借阅申请与审批、线下暗号验证交接、图书归还与接力传递、心愿书单发布与认领、消息通知、微信推送提醒及信用分自动化管理等功能。通过引入信用分机制、定时巡查任务和微信实时推送，系统构建了一套完整的风控体系，有效规范了用户的借阅行为，保障了漂流流程的有序运行。系统的设计与实现为高校旧书资源循环利用提供了一种低门槛、高效率的技术解决方案。

**关键词：** 旧书漂流；共享系统；Spring Boot；Vue.js；信用分管理

## Abstract

　　In college campuses, the recycling of used book resources has always been an issue worth attention. Every year, a large number of students face the problem of idle professional textbooks and postgraduate study materials after use. These books are often discarded due to the lack of convenient circulation channels, resulting in resource waste. At the same time, freshmen and students with financial difficulties face the practical needs of high textbook purchase costs and inconvenient access to second-hand study materials. To address these issues, this system designs and implements an online campus used book drifting and sharing platform based on B/S architecture with "public welfare sharing" as its core concept. The system adopts a front-end and back-end separation architecture. The back-end is built on the Spring Boot framework combined with MyBatis for business logic and database interaction, while the front-end is constructed using the Vue.js framework combined with the Element-UI component library for user interface. MySQL relational database is used for data persistence. The system implements functions including user registration, login and review, book information publishing and review, borrowing application and approval, offline code verification for handover, book return and relay circulation, wish list publishing and claiming, message notification, WeChat push reminders, and credit score automation management. By introducing a credit score mechanism, scheduled inspection tasks, and real-time WeChat push notifications, the system has established a comprehensive risk control framework that effectively regulates users' borrowing behavior and ensures the orderly operation of the drifting process. The design and implementation of this system provide a low-barrier and efficient technical solution for the recycling of used book resources in colleges and universities.

**Keywords:** Used Book Drifting; Sharing System; Spring Boot; Vue.js; Credit Score Management

## 1 绪论

### 1.1 研究背景与意义

　　随着我国高等教育规模的持续扩大，高校在校生人数不断攀升，教材及课外读物的需求量与闲置量同步增长。赵俊杰等人的研究指出，截至2022年在校大学生数量约为4655万人，每个学生一年需要15本教材，每年对教材的需求接近6亿册[21]。然而，大部分教学用书仅在一个学期或一个学年内使用，之后便被束之高阁或当作废纸处理。李昊泽等人通过问卷调查发现，本科学生中闲置书籍数目在5本至20本以上的比例高达92.75%，其中有97.1%的书籍具备二次利用的价值，然而大部分书籍被留存、当作废纸出售甚至直接丢弃[2]。Martin等人于2017年对美国676名学生和573名教师进行了大规模调查，发现66%的学生因价格原因未购买教材，其中47%认为不购买教材对成绩产生了负面影响；86%的学生曾因费用延迟购买教材，其中52%认为延迟购买对成绩有负面影响；更有20.6%的学生因教材费用减少了选课数量，33.28%因教材费用延迟或未注册特定课程[22]。这些数据表明，教材获取成本已成为影响学生学业表现的重要障碍，而大量闲置书籍的存在与教材获取困难之间的矛盾日益突出。

　　从资源节约与环境保护的角度来看，旧书循环利用具有显著的生态价值。李昊泽等人的研究指出，全国高校每年毕业生约900万人，按每人每年课本平均重2500克计算，本科学生四年使用的教科书需消费纸张达12万吨，而生产1吨文化纸需要消耗20余棵树龄在20至40年的树木，同时还消耗净水100吨、600度电、1.2吨煤和300千克化工原料，并产生高浓度污水300吨[2]。张君成在《中国新闻出版广电报》的报道中指出，当当网图书循环利用率已达到95%，其图书循环利用的纸张节约量相当于25000棵树木获得保护，16年来图书循环销售已超2亿册[19]。孟令洋等人的调查进一步揭示，枣庄当康文化图书循环示范基地2023年回收约5000吨二手图书（约1000万册），流通率近100%，其中80%来源于各类大学教材[18]。这些数据充分说明，旧书循环利用在环保和资源节约方面具有巨大的潜在价值。

　　与此同时，高校内部旧书流转面临"信息不对称"和"信任缺失"的双重困境。传统的高校二手书交流主要依赖学期末临时设立的"跳蚤市场"或校园二手交易群，这种模式存在明显缺陷：信息发布分散且时效性差，供需双方难以精准匹配；交易时间集中在毕业季，平时需求无法及时满足；缺乏规范的信用体系和交接流程[6]。李国莲等人指出，当前高校校园二手书流通主要通过线下跳蚤市场及QQ群、贴吧、微信朋友圈等渠道，存在信息不对称、消息滞留等问题[17]。Wei在对中国消费者二手书共享态度的研究中发现，82.92%的受访者至少参与过一次二手书共享，但"对陌生人的不信任"和"拥有欲"是两大主要障碍，在线平台的不实用和复杂流程也是关键阻碍因素[25]。Laurenti等人基于计划行为理论在瑞典KTH皇家理工学院的实证研究同样表明，过程风险担忧是阻碍P2P资源共享的主要因素，而学习材料（含书籍）是大学P2P共享平台中供需双方最热门的品类之一[23]。邹宇驰等人从信息共享平台建设的角度，指出平台建设需解决信息聚合、信任机制和流通效率三大核心问题[8]。

　　在市场层面，二手书循环利用已展现出可观的发展潜力。荣沐华以多抓鱼为例的研究表明，截至2021年底多抓鱼二手书籍销售超过1300万本，实际年收入破亿，已实现盈亏平衡，验证了二手书循环利用的巨大市场潜力[20]。刘维对多抓鱼平台的研究指出，66%的欧洲受访消费者表示喜欢购买二手商品，二手书是最热门种类之一，但校园二手教材交易渠道尚未形成规模化和标准化[15]。赵俊杰等人的调研进一步表明，高校学生对购买二手书的意愿达到了87%的比例，教科书和课本占据了77.24%的市场份额[21]。因此，设计一套规范、便捷、可信赖的校园旧书共享平台，不仅是响应绿色可持续发展理念的具体实践，更是满足广大学生实际需求的务实之举。

　　本项目聚焦校园场景，选择构建基于Spring Boot和Vue.js的校园旧书漂流共享系统，主要基于以下考量：系统定位于校园内网环境，学生通过浏览器即可访问，无需下载安装任何客户端软件，降低了使用门槛[5]；以"公益漂流"而非"二手交易"为核心模式，系统无需引入复杂的支付、订单模块，开发周期更可控，技术难度更适配毕业设计的周期要求；同时，在功能设计上侧重解决实际问题——通过信用分机制约束借阅行为，通过暗号验证确保线下交接的安全性，通过定时巡查任务实现自动化管理[6]。

　　从实际价值来看，本系统的设计与实现具有以下意义：对学生而言，系统提供了一个免费获取旧书资源的渠道，降低了学习资料成本，同时通过"漂流足迹"功能增强了阅读的社交属性；对学校而言，旧书漂流是绿色校园建设和节约型校园建设的具体实践场景，有助于培养大学生的资源循环利用意识和环保理念[7]；从技术实践的角度，采用Spring Boot和Vue.js技术栈进行全栈开发，系统涵盖前后端分离、RESTful API设计、数据库建模、定时任务调度、第三方消息推送等多种技术实践，具有较强的综合训练价值。

### 1.2 国内外研究现状

#### 1.2.1 国内研究现状

　　国内对校园旧书循环利用的研究与实践已积累了一定经验，相关研究可大致划分为线下模式探索、线上平台设计、商业模式创新和技术方案演进四个阶段。

　　在早期的线下模式探索阶段，各高校主要通过图书馆或学生会组织线下"图书漂流角"或"图书交换日"等活动，采用人工登记、现场选取的模式[8]。李在东较早关注了大学校园内剔旧书的资源共享问题，提出了通过图书馆主导实现校内图书资源二次流通的设想[6]。马桂英针对高校旧图书、旧教材浪费严重的问题，提出了建设"漂流屋"以及相应网络平台的设计方案，采用线上查找信息、线下交换取书的"O2O"模式实现旧书漂流，并建议在高校图书馆设立漂流屋，在学生宿舍楼下设置旧教材回收处，建立常态化的回收机制[7]。李美等人以"海大时光旧书屋"为例，探索了高校旧书回收再利用的具体实践路径，验证了线下实体旧书屋在校园场景中的可行性[3]。

　　随着互联网技术的发展，不少高校和研究者开始探索线上化的旧书流转方案。张骞中等人基于B/S结构设计了校园网旧书电子商务系统，将系统划分为图书管理子系统、在线购书子系统、网上支付子系统和用户管理子系统四个模块，实现了旧书的在线查询、销售和管理功能[5]。于洁等人提出了大学生二手图书电子商务交易平台的构想，从平台定位、功能模块和运营模式三个维度进行了系统设计[4]。闫锦彪等人研究了校园二手教材网络交易平台的构建方法，提出了基于B/S架构的线上交易方案[12]。赵俊杰等人基于微信小程序云开发技术，设计并实现了校园二手书交易平台，指出高校学生对购买二手书的意愿达到了87%的比例，教科书和课本占据了77.24%的市场份额[21]。李国莲等人以Node.js为服务端语言开发了"云库书屋"微信小程序，创新设计了"贫困生补贴""用户-平台-用户"和"以物易物"三种运营子程序，其中贫困生认证后可享受4折、5折等优惠，体现了平台的社会公益属性[17]。早期系统的技术选型以Java Web传统技术方案为主，近年来，基于Spring Boot和Vue.js的前后端分离架构逐渐成为校园信息系统开发的主流技术路线。鹿志远等人基于Spring Boot+Vue框架设计并实现了"壹点爱"图书共享公益APP，系统功能包括用户注册登录、图书搜索浏览、图书捐赠申请、个人信息管理、社交互动和评价系统，其技术架构与本项目高度一致，验证了该技术栈在图书共享领域的适用性[16]。

　　在运营模式与商业创新方面，国内二手书行业近年来涌现了多抓鱼、孔夫子旧书网等代表性平台。荣沐华以多抓鱼为例，从价值共创视角分析了网络旧书业的创新图书销售模式，指出多抓鱼创新性采用C2B2C交易模式，突破卖家与买家的身份界限，建立了完整的专业翻新流程——审核正盗版及品相、翻新（打磨、清洁污渍、修复破损页面）、臭氧消毒、再包装上架，并根据市场供求关系动态定价[20]。刘维对多抓鱼平台的服务营销策略进行了系统研究，基于7P营销组合理论和STP战略分析，指出多抓鱼存在图书种类不足、定价不够灵活、营销渠道建设不足等问题，建议聚焦细分市场进行多元化业务拓展和社区发展布局[15]。胡洛对孔夫子旧书网APP的用户体验进行了深入研究，基于KANO模型系统剖析了平台用户需求及其优先级，发现订单管理、物流服务等基础功能属必备需求，信息架构优化与交互便捷性属期望需求，社区互动、资讯分享等属魅力需求，并提出重构交互体验、激活社交生态、文化赋能强化品牌定位等优化方向[14]。孟令洋等人调查了枣庄当康文化图书循环示范基地，该基地拥有图书30余万种、1700余万册，为国内70%以上的二手图书经销商提供业务支撑，2023年回收约5000吨二手图书，流通率近100%，并研发了"掏书铺"自营微信小程序，打造了"买、卖、借、换、赠"的24小时图书循环利用体系[18]。张君成的报道指出，当当网图书循环利用率达到95%，回收的二手书经过翻新、消毒、塑封一条龙服务后重新上架，16年来图书循环销售已超2亿册[19]。李荣杰基于孔夫子旧书网线上平台数据，通过构建灰色关联度模型和BP神经网络模型对二手书定价机理进行了定量研究，发现书籍品相、装帧、开本、页数、出版时间、版次、学科门类及原始定价等8个特征与二手书售价关联度较高，为二手书交易平台的定价机制提供了理论依据[13]。

　　在需求调研与问题分析方面，李昊泽等人通过问卷调查发现，本科学生中闲置书籍数目在5本至20本以上的比例高达92.75%，其中有97.1%的书籍具备二次利用的价值，然而大部分书籍被留存、当作废纸出售甚至直接丢弃[2]。该研究从标准化的视角出发，构建了高校旧书循环服务标准体系。邹宇驰等人从信息共享平台建设的角度，论证了大学生二手书再利用信息共享平台的可行性，指出平台建设需解决信息聚合、信任机制和流通效率三大核心问题[8]。郑茜元等人的调研表明，高校二手书市场具有巨大的潜在规模，但市场规范化程度低、信息透明度不足是制约其发展的核心问题[11]。靳浩杰探讨了自助旧书回收柜在校园纸质书籍资源管理中的应用，提出了将智能识别技术与传统回收流程相结合的方案，通过扫描、识别、分类和积分激励等手段提升旧书回收效率[1]。王川等人以内蒙古大学为例，研究了高校二手书籍交易平台的设计与实现，提出了基于B/S架构的线上交易方案[9]。林梦瑶等人从校园纸质垃圾回收利用的角度，研究了基于二手书交易平台的资源循环方案，提出了线上线下相结合的回收模式[10]。然而，现有国内研究的不足之处同样明显：多数系统过度侧重线下硬件投入而忽视线上信息匹配平台的建设；系统设计复杂度与校园实际场景的适配性不匹配，部分系统引入了不必要的支付模块，偏离了"共享"的本质；缺乏有效的信用约束和自动化管理手段，过度依赖人工干预，难以保证长期稳定运营。

#### 1.2.2 国外研究现状

　　在国外，二手书循环利用已形成较为成熟的研究体系和实践模式。国外相关研究可从教材费用影响研究、P2P共享行为理论、校园平台设计实践和技术实现方案四个维度进行梳理。

　　在教材费用影响研究方面，Martin等人于2017年对美国676名学生和573名教师进行了大规模调查，系统分析了教材费用对高等教育中学生学业表现的影响。研究发现，66%的学生因价格原因未购买教材，其中47%认为不购买教材对成绩产生了负面影响；86%的学生曾因费用延迟购买教材，其中52%认为延迟购买对成绩有负面影响；更有20.6%的学生因教材费用减少了选课数量，33.28%因教材费用延迟或未注册特定课程。研究还发现，91%的教师愿意使用开放教材（OER）替代传统教材，但69%的教师不知道OER替代方案的存在。学生对教材费用的情绪极为负面——54.1%的评论为负面，37.1%为极度负面，仅1.5%为正面。该研究从实证角度揭示了教材费用对学生学业决策的深远影响，为校园旧书共享平台的建设提供了强有力的需求论证[22]。

　　在P2P共享行为理论研究方面，Laurenti和Acuna于2020年基于计划行为理论（TPB），在瑞典KTH皇家理工学院对325名学生进行了定量调查，系统研究了大学环境中P2P资源共享平台的行为意向前因。研究发现，态度是行为意向最强的预测因子（r=0.592），其次是感知行为控制（r=0.385）和主观规范（r=0.368）。态度的关键决定因素包括生态可持续性（r=0.519）、归属感（r=0.478）、对他人信任（r=0.407）和熟悉度（r=0.359），而过程风险担忧是主要阻碍因素（r=-0.266）。值得注意的是，经济利益对态度没有显著影响（p>0.05），这与通常的直觉不同。在需求端，一般服务（77.23%）和学习材料（69.23%）是最受欢迎的共享项目；在供给端，学习材料（58.15%）同样位居前列。51.69%的受访者偏好"自由系统"（包括捐赠和二手销售），37.54%偏好混合系统。该研究为校园旧书漂流平台的设计提供了重要的理论指导：平台应优先考虑降低过程风险、增强用户信任和熟悉度，并推荐采用"自由系统"交易模式[23]。

　　在校园平台设计实践方面，Rai和Kumar于2024年设计并实现了UniSync——一个面向大学生的Web应用平台，支持二手教材、文具及相关材料的买卖和交换。UniSync的核心特色是零佣金模式，区别于其他收取高额费用的平台。调查数据显示，60%的学生表示有兴趣使用UniSync，63.9%的用户认为UniSync有助于环境可持续发展，52.8%的学生在购买教材方面面临困难。平台采用Agile开发方法论，集成了聊天系统和聊天机器人功能，部署在Microsoft Azure云平台上[24]。Ajiboye等人于2022年为尼日利亚伊洛林大学设计并实现了在线书店系统，调查发现80%的受访者表示有兴趣在线购买书籍。系统采用三层架构（用户界面层、流程管理层、数据库管理层），技术栈为HTML5、PHP、CSS/Bootstrap框架、MySQL数据库和JavaScript，实现了产品分类浏览、搜索、购物车、配送方式选择和在线支付等功能[26]。Wei于2022年在瑞典隆德大学完成了专门研究中国消费者对二手书共享态度的硕士论文，采用混合方法（在线调查n=281+深度访谈n=6），发现82.92%的受访者至少参与过一次二手书共享，整体态度积极但障碍目前超过动机。前三大动机为寻找已停售/绝版书籍、自由与灵活性、资源节约与可持续生活方式；两大主要障碍为拥有欲和对陌生人的不信任。研究指出，中国的P2P共享模式研究不足（主流为B2C），校园旧书漂流平台填补了这一空白[25]。

　　综合来看，现有国内外研究存在三方面明显不足：第一，功能导向存在偏差，部分系统的设计过度侧重于二手书的"交易"，引入在线支付、订单管理等模块，增加了开发复杂度和系统运营成本，偏离了"以公益共享促进资源循环"的初衷[5]；第二，技术选型与场景适配性不匹配，部分方案采用复杂技术栈或依赖外部硬件设备，不利于在校园内网环境中快速部署和稳定运行；第三，运营机制不够完善，多数系统缺乏有效的信用约束和自动化管理手段，过度依赖人工干预，难以保证长期稳定运营。Wei的研究进一步指出，信任问题是二手书共享的核心障碍，校园环境天然具备信任优势（同学之间），应充分利用[25]。

　　本项目的创新之处在于：第一，以"公益漂流"而非"商业交易"为核心定位，构建了完全免费的图书共享模式，从根本上降低了系统复杂度，区别于张骞中等人设计的包含在线支付子系统的电子商务模式[5]，也不同于于洁等人提出的商业交易平台构想[4]；第二，设计了多维度信用分管理机制，将借阅行为、还书时效、书籍状态纳入量化评价体系，通过定时巡查任务实现逾期自动扣分、超时自动取消等自动化风控，有效保障了漂流流程的规范运行，同时回应了Wei指出的信任问题[25]和Laurenti等人强调的过程风险担忧[23]；第三，引入了线下交接暗号验证机制，系统自动生成六位数字暗号，在图书所有者与借阅者线下会面时进行核验，确保了交接环节的安全性和不可抵赖性，解决了传统O2O模式中线下交接缺乏安全保障的痛点[7]；第四，集成了WxPusher微信推送服务，实现了借阅状态变更、审核结果、逾期提醒等关键节点的实时消息推送，提升了系统的信息触达效率和用户参与度。

### 1.3 研究内容

　　在开发本系统时，选择Java语言作为核心编程语言，后端选用Spring Boot框架构建易于扩展的服务器应用，前端采用Vue.js框架搭建具有良好交互体验的用户界面，通过MyBatis框架实现数据持久层映射，通过MySQL数据库完成数据的可靠存储与高效管理。具体研究内容如下：

　　（1）设计并实现一套基于B/S架构的校园旧书漂流共享系统，采用前后端分离的开发模式，实现前后端通过RESTful API进行数据交互。

　　（2）系统设定管理员与普通用户两种角色，其中管理员具备全面的系统管理权限，负责用户信息审核、图书信息审核、借阅流程管理及系统全局监控；普通用户享有书籍发布、借阅申请、心愿发布、归还传递等核心使用权限。

　　（3）系统实现用户注册登录、图书信息发布与审核、借阅申请与审批、线下暗号验证交接、图书归还与接力传递、心愿书单发布与认领、系统消息通知、微信推送提醒以及信用分自动化管理等核心功能模块。

## 2 相关技术介绍

　　校园旧书漂流共享系统基于Tomcat服务器，利用IntelliJ IDEA作为开发工具进行代码编辑，通过MySQL数据库确保用户数据和图书信息的高效存储与检索。在开发过程中，选用了Spring Boot和Vue.js作为核心框架，利用MyBatis作为ORM持久层框架，搭配Element-UI组件库和WxPusher微信推送服务，有效提升了系统的开发效率和用户体验。

### 2.1 Java技术

　　Java是一种面向对象的通用编程语言，自1995年发布以来，凭借其"一次编写，到处运行"的跨平台特性、强大的内存管理和垃圾回收机制、丰富的标准库及成熟的生态系统，长期占据企业级应用开发的重要位置。Java应用的源代码首先被编译为平台无关的字节码，随后由各平台上的Java虚拟机解释执行或通过即时编译转化为本地机器码运行。这种"中间表示层+虚拟机"的架构设计赋予了Java优秀的跨平台能力。

　　在Web应用安全领域，Java内置了完善的安全机制，包括字节码验证、类加载器隔离、安全管理器和访问控制策略等，能够有效保护应用程序免受常见网络攻击和威胁。Java还为Java Servlets API、JavaServer Pages以及基于Spring框架的Web开发提供了全面的支持。在本项目中，选用Java作为后端开发语言，主要基于其成熟的生态系统、丰富的第三方依赖库和稳定完善的开发工具链，能够确保系统在毕业设计周期内高效、高质量地完成。

### 2.2 Spring Boot框架

　　Spring Boot是由Pivotal团队基于Spring框架开发的全新一代Java应用快速开发框架。它在Spring框架的基础上，通过"约定优于配置"的设计理念，极大地简化了Spring应用的项目搭建、配置管理和开发部署流程。Spring Boot内置了Tomcat、Jetty等嵌入式Web服务器，开发者无需额外部署WAR包即可通过主类直接启动应用。

　　Spring Boot框架具备以下核心特性：自动配置功能能够根据项目引入的Maven依赖自动完成相关基础设施的配置，大幅减少了XML配置和Java注解配置的工作量；起步依赖（Starter）将常用技术栈的依赖进行聚合打包，开发者只需引入一个starter即可获得全套依赖；Actuator模块提供了生产环境所需的监控和管理端点，支持实时追踪应用状态、监控性能指标及诊断潜在问题。

　　在本项目中，Spring Boot框架作为后端服务的核心框架，承担了Web请求接收分发、业务逻辑层组织协调、数据访问层集成、事务管理、定时任务调度及全局异常处理等职责。通过引入spring-boot-starter-web和mybatis-spring-boot-starter等起步依赖，项目在极少的配置下完成了Web服务、数据库连接池及跨域访问等功能的基础搭建。项目采用Spring Boot 2.5.6版本，主启动类通过@SpringBootApplication注解标识，同时启用@EnableScheduling注解以支持定时任务调度，启用@EnableTransactionManagement注解以支持声明式事务管理。

### 2.3 Vue.js框架

　　Vue.js是一套用于构建用户界面的渐进式JavaScript框架，由尤雨溪于2014年发布。与React和Angular等同类框架相比，Vue.js的核心特性在于其"渐进式"的设计理念——框架本身只关注视图层，可以自底向上逐层应用，开发者可根据项目需求灵活选择生态系统中的工具库。

　　Vue.js的核心技术亮点包括：基于虚拟DOM的差异化更新算法，能够高效地计算视图变更的最小更新集合，实现页面的高效渲染和更新；响应式数据绑定机制，通过Object.defineProperty对数据进行劫持监听，实现了数据变化时视图的自动更新；单文件组件化开发模式，将HTML模板、JavaScript逻辑和CSS样式封装在同一个.vue文件中，优化了代码的结构布局，为后续维护工作带来了便利，促进了团队协作的顺畅进行。

　　在本项目中，Vue.js前端框架与Element-UI组件库配合使用，构建了以管理后台为基准风格的用户界面。通过Vue Router实现了页面路由管理，通过Vuex实现了全局状态管理，通过Axios实现了HTTP请求的统一封装和Token拦截认证。前端项目采用Webpack进行模块化打包，开发模式下配置了代理转发以解决跨域问题。

### 2.4 MySQL数据库

　　MySQL是一个功能强大、广泛使用的开源关系型数据库管理系统，由瑞典MySQL AB公司开发，现归属Oracle公司。MySQL数据库以其开源免费、高性能、可扩展性和安全性等特点，成为了众多企业和个人开发者的首选。相较于Oracle、SQL Server等商业数据库，MySQL的零授权成本优势使其在教育、创业和小型项目场景中具有极高的经济可行性。

　　在技术特性方面，MySQL支持多种存储引擎，其中InnoDB引擎支持ACID事务、行级锁和外键约束，适合需要保证数据一致性和完整性的在线事务处理场景。MySQL采用了优化的B+树索引结构和多版本并发控制机制，能够高效地完成大规模数据的查询和事务处理任务。同时，MySQL提供了完善的访问控制和安全管理功能，支持基于用户和IP的精细化权限限制，并提供数据备份、日志恢复等灾难恢复手段。

　　在本项目中，选用MySQL 8.0作为数据库管理系统，数据库名为DB_Book，采用InnoDB存储引擎确保事务的原子性和一致性。数据库配置通过Spring Boot的application.yml文件进行管理，使用HikariCP连接池提供高效的数据库连接管理。

### 2.5 MyBatis框架

　　MyBatis是一款优秀的Java持久层框架，它通过XML配置或注解的方式，将Java接口方法与SQL语句进行映射绑定，实现数据库操作的半自动化管理。相比于Hibernate等全自动ORM框架，MyBatis不强制要求对象与数据库表之间的严格映射关系，开发者具有对SQL语句的直接控制权，能够针对复杂的业务场景编写高度优化的自定义SQL。

　　MyBatis的核心组件包括：SqlSessionFactory作为会话工厂，负责创建用于执行SQL命令的SqlSession实例；Mapper接口定义了数据库操作的方法签名，通过动态代理机制与XML映射文件中的SQL语句关联；动态SQL标签支持根据传入参数的条件动态拼接SQL语句，增强了SQL的灵活性和重用性。

　　在本项目中，采用MyBatis结合XML映射文件的方式进行数据库操作，将复杂的业务查询（如多条件联合搜索、库存扣减的原子性更新等）通过手写SQL实现精确控制。项目通过mybatis-spring-boot-starter 2.0.0版本实现Spring Boot与MyBatis的无缝集成，Mapper接口通过@MapperScan注解进行自动扫描注册。

## 4 系统设计

### 4.1 系统设计目标

　　本研究旨在设计和实现校园旧书漂流共享系统，建立系统化的旧书漂流共享机制，规范图书漂流工作流程。针对本系统的设计目标，做了如下规划：

### 4.2 系统架构设计

　　本系统采用前后端分离的B/S架构，整体架构分为表现层、控制层、业务层、持久层和数据层五个层次，各层之间通过标准接口进行通信，实现了高内聚低耦合的设计目标。系统架构如图4-1所示。

　　图4-1 系统架构图

　　表现层由Vue.js框架和Element-UI组件库构成，负责页面渲染、用户交互和前端数据状态管理。Vue Router实现页面路由管理，Vuex实现全局状态管理，Axios实现HTTP请求的统一封装和Token拦截认证。

　　控制层由Spring Boot的Controller组件构成，负责接收前端HTTP请求、参数校验和响应封装。系统通过@RestController注解标识控制器类，通过@RequestMapping等注解实现请求路径映射。控制层不包含业务逻辑，仅负责请求的转发和响应的格式化。

　　业务层由Service组件构成，负责核心业务逻辑的处理，包括用户认证、图书审核、借阅流程管理、信用分计算、消息推送等。业务层通过@Transactional注解实现声明式事务管理，确保数据操作的原子性和一致性。

　　持久层由MyBatis框架的Mapper接口和XML映射文件构成，负责数据库的增删改查操作。Mapper接口定义了数据操作的方法签名，XML映射文件中编写具体的SQL语句，支持动态SQL和分页查询。

　　数据层由MySQL数据库构成，存储用户信息、图书信息、借阅记录、图书类型、心愿书单和消息通知等业务数据。

### 4.5 系统流程设计

　　系统设计中系统流程设计是指在全面确保系统的各项功能能够精准满足用户的实际需求，通过精心优化业务流程显著提升系统的运行性能和工作效率，为用户提供更加流畅、高效的服务体验。

#### 4.5.1 用户注册登录流程

　　用户注册时，需填写姓名、学号、密码、性别、所属系部等信息，系统首先检查学号是否已被注册，若已注册则提示"该学号已注册"；若未注册则将用户信息写入数据库，默认设置状态为"待审核"（status=0）、身份为"读者"（isAdmin=0）、初始信用分为100分。注册成功后，用户需等待管理员审核通过方可登录。

　　用户登录时，系统通过学号查询数据库中的用户记录，依次进行三重校验：密码校验——比对用户输入的密码与数据库中存储的密码是否一致；身份校验——验证用户选择的登录身份（读者/管理员）与数据库记录是否匹配；状态校验——检查账号是否处于正常状态（status=1），若为待审核（status=0）则提示"账号审核中"，若为禁用（status=2）则提示"账号被禁用"。校验全部通过后，系统通过TokenProcessor生成基于MD5和Base64编码的Token令牌，将Token与用户信息存入内存映射表，并将Token和用户信息返回给前端。前端将Token存入Vuex状态管理和localStorage，后续请求通过Token进行身份认证。用户注册登录流程图如图4-7所示。

　　图4-7 用户注册登录流程图

#### 4.5.2 图书发布与审核流程

　　用户发布图书时，首先上传图书封面图片至服务器，系统通过uploadController处理文件上传，将图片保存至服务器指定目录并返回访问路径。用户填写图书名称、作者、分类、书籍总数、寄语简介和交接说明后提交，系统将图书信息写入数据库，默认设置审核状态为"待审核"（auditStatus=0），库存数量自动同步为书籍总数。

　　管理员在图书审核页面查看待审核的图书列表，可查看图书详细信息后决定通过或驳回。审核通过时，系统将auditStatus更新为1，同时向发布者发送站内信通知和微信推送通知；审核驳回时，系统将auditStatus更新为2，记录驳回原因，并向发布者发送包含驳回原因的通知。图书发布与审核流程图如图4-8所示。

#### 4.5.3 借阅申请与审批流程

　　用户申请借阅时，系统首先进行三重风控校验：信用分校验——若用户信用分低于60分则拒绝申请；自我借阅校验——禁止用户借阅自己发布的图书；身份校验——管理员账号不可参与借阅流转。校验通过后，系统创建借阅记录，设置流转状态为"待审核"（state=0），记录申请时间和申请理由，同时向图书发布者发送站内信和微信推送通知。

　　图书发布者（或管理员）审核借阅申请时，若同意则系统执行以下操作：扣减图书库存1本，若库存降为0则标记为"无库存"；生成六位随机数字交接暗号；将流转状态更新为"待交接"（state=4）；向申请人发送包含交接暗号和交接说明的通知。若驳回则将流转状态更新为"已驳回"（state=3），记录驳回原因，并向申请人发送驳回通知。借阅申请与审批流程图如图4-9所示。

#### 4.5.4 交接暗号验证流程

　　审核通过后，借阅双方约定时间地点进行线下交接。图书发布者在系统中输入借阅者出示的六位数字暗号，系统验证暗号的正确性。验证通过后，系统进行信用分二次校验——若借阅者信用分已跌破60分则阻断交接；校验通过后，将流转状态更新为"漂流中"（state=1），记录借阅时间，并向发布者发放信用分奖励（+3分，每日上限5分，封顶100分）。交接暗号验证流程图如图4-10所示。

## 6 系统测试

　　测试作为保障系统质量的核心环节，目的在通过系统化的检测流程来识别并修正开发阶段可能潜藏的错误，从而确保软件或系统的稳定运行。通过制定严谨的测试方案、设计全面的测试用例，以及执行精确的测试流程，能够系统地识别并纠正开发过程中可能存在的错误和缺陷。

### 6.1 测试方案

　　本测试方案旨在全面验证校园旧书漂流共享系统的功能完备性、性能可靠性、安全防护性以及跨平台兼容性，确保系统能够高效、稳定地满足业务需求，为用户提供安全、流畅的使用体验。

#### 6.1.1 测试范围

　　功能测试：全面覆盖用户注册、登录、图书浏览、图书发布与审核、借阅申请与审批、交接暗号验证、图书归还传递、心愿广场、消息通知等核心功能，确保每个功能点都能正常运行并达到预期效果。

　　单元测试：在本系统的开发过程中，针对其各个独立的模块进行了详尽的单元测试，目的在于验证这些基本组成单元的正确性和可靠性。

## 总结与展望

　　校园旧书漂流共享系统采用Spring Boot、Vue.js框架，为高校旧书资源的循环利用提供了强有力的技术支撑，实现了用户注册登录与审核、图书信息发布与审核、借阅申请与审批、线下暗号验证交接、图书归还与接力传递、心愿书单发布与认领、消息通知、微信推送提醒及信用分自动化管理等功能。该系统不仅数据处理能力强、用户体验好、扩展性强，还实现了后端与前端之间的数据交互，便于用户查看。

　　该校园旧书漂流共享系统的功能主要包括以下几点：

　　（1）管理员可以审核用户注册申请，审核图书发布信息，管理图书类型，监控借阅流程，对异常记录执行强制归还或强制收回等处置操作。

　　（2）普通用户可以登录该系统浏览漂流图书信息，发布闲置旧书，申请借阅，查看漂流足迹，发布心愿书单，管理个人信息，接收系统消息通知和微信推送提醒。

　　（3）系统通过信用分机制和定时巡查任务，实现了逾期自动扣分、超时自动取消等自动化风控，有效保障了漂流流程的规范运行。

　　经过测试，确认校园旧书漂流共享系统已实现了既定的功能需求与设计逻辑。系统不仅运行稳定，各模块间协同流畅，有效规避了众多常识性和潜在性的技术风险。同时，系统展现出强大的安全性，能够准确过滤掉大部分非法请求，确保了数据的安全与完整性。

　　然而，本系统仍存在一些可以改进的方向：在用户体验方面，可以引入图书智能推荐功能，根据用户的借阅历史和偏好进行个性化推荐；在社交互动方面，可以增加读书笔记分享和书友交流社区功能，增强平台的社交属性；在技术架构方面，可以将Token存储从内存映射升级为Redis缓存，提升系统的可扩展性和集群部署能力；在移动端适配方面，可以开发微信小程序版本，进一步降低使用门槛。总之，校园旧书漂流共享系统还需要不断优化，为用户提供更加优质、高效的服务，推动高校旧书资源的循环利用和绿色校园建设。

#### A.4 定时巡查任务核心代码

　　定时巡查任务由BorrowTask实现，每59分钟执行一次。主要完成两项工作：一是巡查超时未审核和超时未交接的借阅记录并自动取消；二是巡查已逾期的借阅记录并对逾期用户每日扣除2信用分。

```java
@Component
public class BorrowTask {

    @Resource
    private BorrowMapper borrowMapper;
    @Resource
    private UserMapper userMapper;
    @Resource
    private BookInfoMapper bookInfoMapper;
    @Resource
    private MessageMapper messageMapper;

    @Scheduled(cron = "0 */59 * * * ?")
    public void systemPatrolTask() {
        System.out.println("【系统巡查卫士】开始执行自动化风控巡查...");
        long now = System.currentTimeMillis();
        long threeDaysMillis = 3L * 24 * 60 * 60 * 1000;

        Map<String, Object> allParams = new HashMap<>();
        allParams.put("begin", 0);
        allParams.put("size", 10000);
        List<Borrow> allBorrows = borrowMapper.selectAllByLimit(allParams);

        for (Borrow borrow : allBorrows) {
            if ((borrow.getState() == 0 || borrow.getState() == 4) 
                && borrow.getApplytime() != null) {
                long timeout = threeDaysMillis;
                if (borrow.getBorrowreason() != null 
                    && borrow.getBorrowreason().contains("测试")) {
                    timeout = 3L * 60 * 1000;
                }
                if (now - borrow.getApplytime().getTime() > timeout) {
                    int oldState = borrow.getState();
                    borrow.setState(7);
                    borrow.setReturnmsg("【系统强制取消】超出处理期限，系统已自动释放该申请。");
                    borrowMapper.updateByPrimaryKeySelective(borrow);
                    BookInfo book = bookInfoMapper.selectByPrimaryKey(borrow.getBookid());
                    if (oldState == 4 && book != null) {
                        book.setInventory(book.getInventory() + 1);
                        if (book.getInventory() > 0) book.setIsborrowed(0);
                        bookInfoMapper.updateByPrimaryKeySelective(book);
                    }
                    messageMapper.insert(new Message(borrow.getUserid(),
                        "【系统通知】您对《" + (book != null ? book.getBookname() : "")
                        + "》的申请因超时未处理，已被系统自动取消。"));
                    if (book != null && book.getUploaderid() != null) {
                        messageMapper.insert(new Message(book.getUploaderid(),
                            "【系统通知】由于超时未处理，针对《" + book.getBookname()
                            + "》的借阅申请已被系统强制释放，若已扣库存则现已回退。"));
                    }
                }
            }
            if (borrow.getState() == 1 && borrow.getBorrowtime() != null) {
                int allowDays = (borrow.getBorrowDays() != null) 
                    ? borrow.getBorrowDays() : 30;
                long borrowedMillis = now - borrow.getBorrowtime().getTime();
                long allowMillis = (long) allowDays * 24 * 60 * 60 * 1000;
                if (borrowedMillis > allowMillis || allowDays == 0) {
                    User borrower = userMapper.selectByPrimaryKey(borrow.getUserid());
                    if (borrower != null && borrower.getCreditScore() != null) {
                        int currentScore = borrower.getCreditScore();
                        if (currentScore > 0) {
                            int newScore = Math.max(0, currentScore - 2);
                            borrower.setCreditScore(newScore);
                            userMapper.updateByPrimaryKeySelective(borrower);
                            String msg = "【逾期惩罚】您的借阅已逾期！系统已扣除您 2 信用分。当前剩余："
                                + newScore + " 分。";
                            messageMapper.insert(new Message(borrower.getUserid(), msg));
                        }
                    }
                }
            }
        }
        System.out.println("【系统巡查卫士】本轮巡查结束！");
    }
}
```

#### A.6 交接暗号验证核心代码

　　交接暗号验证功能由BorrowServiceImpl实现，验证暗号正确性后进行信用分二次校验，校验通过后将流转状态更新为"漂流中"并触发发布者信用分回血奖励。

```java
@Override
@Transactional
public R verifyCode(Integer borrowId, String secretCode) {
    Borrow borrow = borrowMapper.selectByPrimaryKey(borrowId);
    if (borrow == null) return R.error("记录不存在");
    if (borrow.getState() != 4) return R.error("当前状态不支持验证暗号");
    if (borrow.getSecretCode() == null 
        || !borrow.getSecretCode().equals(secretCode)) {
        return R.error("暗号错误，请核对后再试！");
    }
    User borrower = userMapper.selectByPrimaryKey(borrow.getUserid());
    if (borrower != null && borrower.getCreditScore() != null 
        && borrower.getCreditScore() < 60) {
        return R.error("阻断交易！该借阅者近期违规信用已跌破60，系统强制终止交接！");
    }
    borrow.setState(1);
    borrow.setBorrowtime(new Date());
    borrowMapper.updateByPrimaryKeySelective(borrow);
    BookInfo book = bookInfoMapper.selectByPrimaryKey(borrow.getBookid());
    if (book != null && book.getUploaderid() != null) {
        User uploader = userMapper.selectByPrimaryKey(book.getUploaderid());
        if (uploader != null 
            && (uploader.getCreditScore() == null || uploader.getCreditScore() < 100)) {
            java.text.SimpleDateFormat sdf = new java.text.SimpleDateFormat("yyyy-MM-dd");
            String todayStr = sdf.format(new java.util.Date());
            String updateStr = uploader.getScoreUpdateDate() == null 
                ? "" : sdf.format(uploader.getScoreUpdateDate());
            int todayAdded = uploader.getTodayAddScore() == null 
                ? 0 : uploader.getTodayAddScore();
            if (!todayStr.equals(updateStr)) {
                todayAdded = 0;
                uploader.setScoreUpdateDate(new java.util.Date());
            }
            int currentScore = uploader.getCreditScore() == null 
                ? 100 : uploader.getCreditScore();
            if (todayAdded < 5 && currentScore < 100) {
                int canAdd = Math.min(3, 5 - todayAdded);
                int finalScore = Math.min(100, currentScore + canAdd);
                int actualAdded = finalScore - currentScore;
                if (actualAdded > 0) {
                    uploader.setCreditScore(finalScore);
                    uploader.setTodayAddScore(todayAdded + actualAdded);
                    userMapper.updateByPrimaryKeySelective(uploader);
                    messageMapper.insert(new Message(uploader.getUserid(),
                        "【信用奖励】成功交接给下一位书友！本次恢复 " + actualAdded 
                        + " 分 (今日已累计恢复 " + (todayAdded + actualAdded) 
                        + "/5 分)，当前：" + finalScore + " 分。"));
                }
            }
        }
    }
    return R.ok("暗号正确！交接成功，书籍正式进入漂流中。");
}
```

#### A.9 Token生成与用户会话管理核心代码

　　TokenProcessor采用单例模式实现，通过MD5和Base64编码生成唯一Token令牌，使用ConcurrentHashMap实现线程安全的Token与用户信息映射管理。

```java
public class TokenProcessor {
    private TokenProcessor() {}
    private static final TokenProcessor instance = new TokenProcessor();
    private static final Map<String, User> tokenMap = new ConcurrentHashMap<>();

    public static TokenProcessor getInstance() { return instance; }

    public String generateToken() {
        String token = (System.currentTimeMillis() + new Random().nextInt(999999999)) + "";
        try {
            MessageDigest md = MessageDigest.getInstance("md5");
            byte[] md5 = md.digest(token.getBytes());
            return Base64.getEncoder().encodeToString(md5);
        } catch (NoSuchAlgorithmException e) {
            e.printStackTrace();
        }
        return null;
    }

    public void saveUser(String token, User user) {
        if (token != null && user != null) tokenMap.put(token, user);
    }

    public User getUser(String token) {
        return token == null ? null : tokenMap.get(token);
    }

    public void removeUser(String token) {
        if (token != null) tokenMap.remove(token);
    }
}
```

#### A.15 前端全局路由守卫

　　前端全局路由守卫通过Vue Router的beforeEach钩子实现，负责Token校验、动态路由加载和未登录用户的重定向，确保系统页面的访问安全性。

```javascript
import router from './router'
import store from './store'
import { Message } from 'element-ui'
import NProgress from 'nprogress'
import 'nprogress/nprogress.css'
import { getToken } from '@/utils/auth'
import getPageTitle from '@/utils/get-page-title'

NProgress.configure({ showSpinner: false })

const whiteList = ['/login', '/register']

router.beforeEach(async(to, from, next) => {
  NProgress.start()
  document.title = getPageTitle(to.meta.title)
  const hasToken = getToken()

  if (hasToken) {
    if (to.path === '/login') {
      next({ path: '/' })
      NProgress.done()
    } else {
      const hasRoles = store.getters.roles && store.getters.roles.length > 0
      if (hasRoles) {
        next()
      } else {
        try {
          const { roles } = await store.dispatch('user/getInfo')
          const accessRoutes = await store.dispatch('permission/generateRoutes', roles)
          router.addRoutes(accessRoutes)
          next({ ...to, replace: true })
        } catch (error) {
          await store.dispatch('user/resetToken')
          console.error('Token失效或系统错误，自动跳转登录页:', error)
          next(`/login?redirect=${to.path}`)
          NProgress.done()
        }
      }
    }
  } else {
    if (whiteList.indexOf(to.path) !== -1) {
      next()
    } else {
      next(`/login?redirect=${to.path}`)
      NProgress.done()
    }
  }
})

router.afterEach(() => {
  NProgress.done()
})
```

### 附录B 外文资料

　　本附录收录了与毕业设计课题相关的外文文献原文，选自Laurenti和Acuna于2020年发表在Sustainable Production and Consumption期刊上的研究论文"Exploring antecedents of behavioural intention and preferences in online peer-to-peer resource sharing in a Swedish university setting"，该文献系统研究了大学环境中P2P资源共享平台的行为意向前因，为校园旧书漂流共享系统的设计提供了重要的理论指导。

```text
Exploring antecedents of behavioural intention and preferences in online peer-to-peer resource sharing in a Swedish university setting

Rafael Laurenti a,*, Fernando Manuel Barrios Acuna b

a KTH Royal Institute of Technology, Department of Sustainable Development, Environmental Science and Engineering, Stockholm, Sweden
b KTH Royal Institute of Technology, School of Industrial Engineering and Management, Stockholm, Sweden

ABSTRACT

The sharing economy is expected to contribute to sustainability, but there is limited knowledge about what drives behavioural intention to share resources in online peer-to-peer (P2P) platforms, especially in a university setting. This study aims to explore the antecedents of behavioural intention and preferences in online P2P resource sharing among university students and staff. The research was conducted at KTH Royal Institute of Technology in Stockholm, Sweden. A qualitative phase with semi-structured interviews (n=7) informed a quantitative phase with a survey (n=325). The Theory of Planned Behaviour (TPB) was used as the theoretical framework. The results show that attitude is the strongest predictor of behavioural intention (r=.592), followed by perceived behavioural control (r=.385) and subjective norm (r=.368). Key determinants of attitude include ecological sustainability (r=.519), sense of belonging (r=.478), trust in others (r=.407), and familiarity (r=.359). Process risk concern is a major barrier (r=-.266). Notably, economic benefit does not have a significant effect on attitude (p>.05). On the demand side, general services (77.23%) and study materials (69.23%) are the most popular items to share. On the supply side, general services (64.65%) and study materials (58.15%) also rank at the top. Regarding preferences, 51.69% of respondents prefer a "free system" (including donations and second-hand sales), while 37.54% prefer a mixed system. The findings suggest that platform design should prioritize reducing process risk, enhancing user trust and familiarity, and promoting ecological sustainability as a core value.

Keywords: Sharing economy; Peer-to-peer sharing; Theory of Planned Behaviour; University; Sustainability; Behavioural intention

1. Introduction

The sharing economy has emerged as a socio-economic model that enables individuals to share underutilized resources through online platforms, potentially contributing to more sustainable consumption patterns (Botsman and Rogers, 2010). In university settings, where communities share physical spaces and have high levels of interpersonal trust, peer-to-peer (P2P) resource sharing platforms hold particular promise for reducing waste and promoting circular resource flows.

Despite the growing interest in sharing economy platforms, there remains limited understanding of what drives behavioural intention to participate in online P2P resource sharing, especially within university communities. Previous research has primarily focused on commercial sharing platforms such as Airbnb and Uber, while community-based sharing initiatives in educational settings have received less attention.

This study addresses this gap by exploring the antecedents of behavioural intention and preferences in online P2P resource sharing among students and staff at KTH Royal Institute of Technology in Stockholm, Sweden. The Theory of Planned Behaviour (TPB) serves as the theoretical framework, examining how attitudes, subjective norms, and perceived behavioural control influence sharing intentions.

2. Theoretical framework and hypotheses

The Theory of Planned Behaviour (Ajzen, 1991) posits that behavioural intention is determined by three factors: attitude toward the behaviour, subjective norm, and perceived behavioural control. In the context of P2P resource sharing, we extend the TPB model by incorporating additional constructs relevant to sharing behaviour in university settings.

Attitude toward sharing is influenced by multiple factors. Ecological sustainability concerns may drive positive attitudes, as sharing reduces the environmental footprint of consumption (Heinrichs, 2013). A sense of belonging to the university community may foster sharing behaviour, as individuals who identify with their community are more likely to engage in pro-social actions (Belk, 2010). Trust in others is essential for sharing platforms, as users must believe that their resources will be returned in good condition (Botsman, 2013). Familiarity with sharing platforms reduces uncertainty and increases willingness to participate. Conversely, concerns about process risks—such as damage to shared items, time delays, or misuse—may negatively affect attitudes.

Based on the theoretical framework, we propose the following hypotheses:

H1: Attitude toward P2P resource sharing positively influences behavioural intention.
H2: Subjective norm positively influences behavioural intention.
H3: Perceived behavioural control positively influences behavioural intention.
H4: Ecological sustainability concern positively influences attitude.
H5: Sense of belonging positively influences attitude.
H6: Trust in others positively influences attitude.
H7: Familiarity with sharing platforms positively influences attitude.
H8: Process risk concern negatively influences attitude.
H9: Economic benefit positively influences attitude.

3. Methodology

This study adopted a mixed-methods approach. In the qualitative phase, semi-structured interviews were conducted with seven members of the KTH community to explore their perceptions and experiences with resource sharing. The interview findings informed the design of the quantitative survey.

In the quantitative phase, an online survey was distributed to KTH students and staff, yielding 325 valid responses. The survey measured constructs using validated scales adapted from previous studies. All items were measured on a 5-point Likert scale ranging from 1 (strongly disagree) to 5 (strongly agree).

4. Results

4.1 Predictors of behavioural intention

The results confirm that attitude is the strongest predictor of behavioural intention (r=.592, p<.001), followed by perceived behavioural control (r=.385, p<.001) and subjective norm (r=.368, p<.001). Together, these three TPB constructs explain 42.7% of the variance in behavioural intention.

4.2 Determinants of attitude

Among the determinants of attitude, ecological sustainability shows the strongest correlation (r=.519, p<.001), followed by sense of belonging (r=.478, p<.001), trust in others (r=.407, p<.001), and familiarity (r=.359, p<.001). Process risk concern is negatively correlated with attitude (r=-.266, p<.001), confirming its role as a barrier to sharing.

Notably, economic benefit does not have a statistically significant effect on attitude (p>.05), contradicting the common assumption that financial incentives are the primary driver of sharing behaviour. This finding suggests that in university settings, non-economic motivations such as sustainability and community belonging may be more important than monetary savings.

4.3 Sharing preferences

On the demand side, the most popular categories for sharing are general services (77.23%), study materials (69.23%), tools and equipment (53.85%), and sports and outdoor items (46.46%). On the supply side, general services (64.65%), study materials (58.15%), tools and equipment (43.08%), and sports and outdoor items (38.15%) are the most commonly offered categories.

Regarding system preferences, 51.69% of respondents prefer a "free system" that includes donations and second-hand sales, 37.54% prefer a mixed system combining free and paid sharing, and 10.77% prefer a "paid system" with rental fees.

5. Discussion

The findings have important implications for the design and implementation of P2P resource sharing platforms in university settings. First, the strong influence of ecological sustainability on attitude suggests that platforms should prominently communicate the environmental benefits of sharing. Second, the importance of trust and familiarity indicates that platforms should incorporate trust-building mechanisms such as user verification, ratings, and reviews. Third, the negative effect of process risk concern highlights the need for simple, transparent sharing procedures with clear rules for damage and dispute resolution.

The finding that economic benefit does not significantly influence attitude challenges the assumption that financial incentives are necessary to drive sharing behaviour. In university communities, where social cohesion and shared identity are strong, non-economic motivations may be sufficient to encourage participation. This supports the design of "free system" sharing platforms that focus on community building rather than monetary transactions.

6. Conclusions

This study contributes to the understanding of behavioural intention in online P2P resource sharing within university settings. The results demonstrate that attitude—driven primarily by ecological sustainability, sense of belonging, and trust—is the strongest predictor of sharing intention. Process risk concern is the main barrier, while economic benefit plays a negligible role. Study materials are among the most popular categories for both demand and supply, highlighting the potential for book-sharing platforms in university communities. The preference for "free system" models suggests that donation-based and second-hand sharing platforms may be more appealing than rental-based systems in educational settings.
```

```text
探索瑞典大学环境中在线P2P资源共享的行为意向前因与偏好

Rafael Laurenti, Fernando Manuel Barrios Acuna

a 瑞典斯德哥尔摩，KTH皇家理工学院，可持续发展、环境科学与工程系
b 瑞典斯德哥尔摩，KTH皇家理工学院，工业工程与管理学院

摘要

共享经济有望促进可持续发展，但关于什么驱动了在线点对点（P2P）平台上资源共享的行为意向，尤其是在大学环境中的研究知识仍然有限。本研究旨在探索大学师生在线P2P资源共享中行为意向和偏好的前因。研究在瑞典斯德哥尔摩的KTH皇家理工学院进行。定性阶段采用半结构化访谈（n=7），为定量阶段的调查（n=325）提供信息。采用计划行为理论（TPB）作为理论框架。结果表明，态度是行为意向最强的预测因子（r=0.592），其次是感知行为控制（r=0.385）和主观规范（r=0.368）。态度的关键决定因素包括生态可持续性（r=0.519）、归属感（r=0.478）、对他人信任（r=0.407）和熟悉度（r=0.359）。过程风险担忧是主要阻碍因素（r=-0.266）。值得注意的是，经济利益对态度没有显著影响（p>0.05）。在需求端，一般服务（77.23%）和学习材料（69.23%）是最受欢迎的共享项目。在供给端，一般服务（64.65%）和学习材料（58.15%）同样位居前列。关于偏好，51.69%的受访者偏好"自由系统"（包括捐赠和二手销售），37.54%偏好混合系统。研究结果表明，平台设计应优先考虑降低过程风险、增强用户信任和熟悉度，并将生态可持续性作为核心价值进行推广。

关键词：共享经济；点对点共享；计划行为理论；大学；可持续性；行为意向

1. 引言

共享经济作为一种社会经济模式已经兴起，它使个人能够通过在线平台共享未充分利用的资源，有可能促进更可持续的消费模式（Botsman和Rogers，2010）。在大学环境中，社区共享物理空间且具有较高的人际信任水平，点对点（P2P）资源共享平台在减少浪费和促进循环资源流动方面具有特殊的前景。

尽管对共享经济平台的兴趣日益增长，但对于什么驱动了在线P2P资源共享的行为意向，尤其是在大学社区中的理解仍然有限。以往的研究主要集中在Airbnb和Uber等商业共享平台上，而教育环境中基于社区的共享倡议受到的关注较少。

本研究通过探索KTH皇家理工学院师生在线P2P资源共享中行为意向和偏好的前因来填补这一空白。计划行为理论（TPB）作为理论框架，考察态度、主观规范和感知行为控制如何影响共享意向。

2. 理论框架与假设

计划行为理论（Ajzen，1991）认为，行为意向由三个因素决定：对行为的态度、主观规范和感知行为控制。在P2P资源共享的背景下，我们通过纳入与大学环境中共享行为相关的额外构念来扩展TPB模型。

对共享的态度受多种因素影响。生态可持续性关注可能驱动积极态度，因为共享减少了消费的环境足迹（Heinrichs，2013）。对大学社区的归属感可能促进共享行为，因为认同其社区的个人更可能参与亲社会行动（Belk，2010）。对他人的信任对共享平台至关重要，因为用户必须相信他们的资源会完好归还（Botsman，2013）。对共享平台的熟悉度降低了不确定性并增加了参与意愿。相反，对过程风险的担忧——如共享物品损坏、时间延误或滥用——可能对态度产生负面影响。

基于理论框架，我们提出以下假设：

H1：对P2P资源共享的态度正向影响行为意向。
H2：主观规范正向影响行为意向。
H3：感知行为控制正向影响行为意向。
H4：生态可持续性关注正向影响态度。
H5：归属感正向影响态度。
H6：对他人信任正向影响态度。
H7：对共享平台的熟悉度正向影响态度。
H8：过程风险担忧负向影响态度。
H9：经济利益正向影响态度。

3. 研究方法

本研究采用混合方法。在定性阶段，对KTH社区的七名成员进行了半结构化访谈，以探索他们对资源共享的感知和经验。访谈结果为定量调查的设计提供了信息。

在定量阶段，向KTH师生分发了在线调查，获得325份有效回复。调查使用从以往研究中改编的已验证量表来测量构念。所有项目均采用5点李克特量表，范围从1（非常不同意）到5（非常同意）。

4. 结果

4.1 行为意向的预测因子

结果证实，态度是行为意向最强的预测因子（r=0.592，p<0.001），其次是感知行为控制（r=0.385，p<0.001）和主观规范（r=0.368，p<0.001）。这三个TPB构念共同解释了行为意向42.7%的方差。

4.2 态度的决定因素

在态度的决定因素中，生态可持续性显示出最强的相关性（r=0.519，p<0.001），其次是归属感（r=0.478，p<0.001）、对他人信任（r=0.407，p<0.001）和熟悉度（r=0.359，p<0.001）。过程风险担忧与态度负相关（r=-0.266，p<0.001），确认了其作为共享障碍的作用。

值得注意的是，经济利益对态度没有统计学上的显著影响（p>0.05），这与财务激励是共享行为主要驱动力的普遍假设相矛盾。这一发现表明，在大学环境中，可持续性和社区归属等非经济动机可能比货币节省更为重要。

4.3 共享偏好

在需求端，最受欢迎的共享类别是一般服务（77.23%）、学习材料（69.23%）、工具和设备（53.85%）以及运动和户外用品（46.46%）。在供给端，一般服务（64.65%）、学习材料（58.15%）、工具和设备（43.08%）以及运动和户外用品（38.15%）是最常提供的类别。

关于系统偏好，51.69%的受访者偏好包含捐赠和二手销售的"自由系统"，37.54%偏好结合免费和付费共享的混合系统，10.77%偏好收取租赁费的"付费系统"。

5. 讨论

研究结果对大学环境中P2P资源共享平台的设计和实施具有重要启示。首先，生态可持续性对态度的强烈影响表明，平台应突出传达共享的环境效益。其次，信任和熟悉度的重要性表明，平台应纳入信任建设机制，如用户验证、评分和评论。第三，过程风险担忧的负面影响凸显了需要简单、透明的共享程序，并为损坏和争议解决制定明确的规则。

经济利益不显著影响态度的发现挑战了财务激励是驱动共享行为所必需的假设。在社会凝聚力和共同认同感较强的大学社区中，非经济动机可能足以鼓励参与。这支持了专注于社区建设而非货币交易的"自由系统"共享平台的设计。

6. 结论

本研究有助于理解大学环境中在线P2P资源共享的行为意向。结果表明，态度——主要由生态可持续性、归属感和信任驱动——是共享意向最强的预测因子。过程风险担忧是主要障碍，而经济利益的作用微乎其微。学习材料是需求和供给双方最受欢迎的类别之一，凸显了图书共享平台在大学社区中的潜力。对"自由系统"模式的偏好表明，在教育环境中，基于捐赠和二手共享的平台可能比基于租赁的系统更具吸引力。
```
